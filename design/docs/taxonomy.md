1 · How the two systems differ
Genres — a fixed set of 12. One per palette colour. This is what the library sorts and filters by. A work carries one primary genre and may carry a second, never more.
Tags — an open set of 242 seeded across 7 groups. Attached to individual works. The user adds freely; the seed exists so the app is useful on day one and so incoming metadata has something to match against.

Why exactly 12 genres. Tag.colorIndex is 0–11, so the genre set and the genre palette are the same size by design. A thirteenth genre means a thirteenth colour.

The one non-obvious choice: Progression & Cultivation is top-level. Every mainstream taxonomy — Goodreads, AniList, BISAC — files xianxia, LitRPG and system novels under Fantasy. Giving it its own colour, and the primary accent specifically, is the clearest signal that this vocabulary was built for this shelf rather than borrowed.
3 · Tags — 242 across 7 groups
Grouping is borrowed from MangaDex, which splits its vocabulary into format, genre, theme and content warning rather than one flat list. A flat list of this size is unusable; grouped, it is navigable.
For design: these are the real strings. Use them when laying out chips and the tag picker. Layouts built against placeholder text break on contact with the actual extremes — System and War at one end, Depictions of Cruelty and Heavens/Immortal Realm at the other.

4 · Rules
Never auto-create a genre. The 12 are fixed. Unmatched incoming values become tags or are discarded.
Never auto-create a tag from Open Library subjects. OL subjects are user-submitted and include entries like &quot;Accessible book&quot; and &quot;New York Times bestseller&quot;. Match against the seed list and discard the rest, or the tag table fills with junk within a week.
Genre is suggested, never applied. Same rule as series detection — a chip the user confirms.
A work carries at most two genres. More than that and the colour coding stops meaning anything.
Content warnings are opt-in. Off by default in Settings. When off, those tags neither display nor get created on ingest. When on, they must be distinguishable from ordinary tags at a glance.
Merge on normalizedName. &quot;sci-fi&quot;, &quot;Sci-Fi&quot; and &quot;Science Fiction&quot; must not become three tags.
5 · Deliberate omissions
Ecchi, harem, smut, adult, yaoi/yuri as genres — dropped on ingest. NovelUpdates and AniList carry these heavily; none describe this reader’s stated taste, and they would pollute filtering. Straightforward to add back if that turns out wrong.
Demographic labels (shounen, seinen, shoujo, josei) are tags, not genres. They describe a publishing bracket, not content. Treating them as genres is a large part of why manhwa filtering is broken in other apps.
&quot;No Ending&quot; and &quot;Dropped by Author&quot; live in the Craft group and are distinct from the endingNone axis field. The tag describes the work; the axis records the reader’s judgment. Both are kept.
Format (book / novel / manhwa) is a field on the work, not a tag. It is never duplicated here.
